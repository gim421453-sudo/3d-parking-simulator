## PDC 사각형 오류의 실제 원인

`src/pdc/overlay.ts` `buildCameraTiles()` (v0.4.4~v0.6.0):
1. 판 방향이 **항상 차량 가로축**(차량 로컬 ±x) — 장애물 표면 방향을 쓰지 않았다.
2. 차체 폭 ±1.6m 를 0.3m 칸으로 나누고 **칸마다 가장 가까운 히트의 "차량 축 방향 거리"** 에 판을 세웠다 → 같은 비스듬한 벽이 칸마다 다른 깊이(계단), 판이 표면과 떨어져 공중에 뜸.
3. 칸 병합 기준이 물체가 아니라 "같은 단계 + 거리차 0.3m" → 다른 물체끼리 합쳐지거나 같은 물체가 쪼개짐.
4. 차체 옆(폭 밖 1.6m)까지 '정면 판'으로 만들어 후방 둘레에 활 모양으로 늘어섬(S5/S6).
5. 판 높이를 장애물 윗면까지(최대 0.5m) 세워 근접 시 화면을 크게 덮음(S1).

수정(`src/pdc/surfaceWarn.ts`): 센서가 맞춘 **충돌체의 실제 면**(OBB 면 ±x/±z, 원기둥 원호)을 따라, 그 면에서 히트가 덮는 구간만 판을 세운다. 판 하나 = (충돌체, 면). 기하를 모르면 히트점 근처 0.6m 이하의 작은 판만. 판 높이 ≤0.38m, 옅은 면 + 밑변/윗변 윤곽. 사라진 물체의 판은 잔상 없이 빠르게 지운다. 밀린 물체·벽 조각은 현재 기하(`colliderOf`: 정적 + `damage.dynamicColliders`)로.

## 위험 우선순위 (`src/pdc/riskRank.ts`)

장애물(충돌체 ID) 하나 = 후보 하나. 간격(차체 외곽까지), 위치(전/후/좌/우/모서리), **현재 기어 방향 + 실제 전륜 조향각으로 차체가 쓸고 갈 영역과의 교차**(정지 중에도), 모서리 스윙, 접근 속도·TTC(움직일 때만), 히트 수.
등급: 1 접촉 직전(≤0.08m) · 2 매우 근접(≤0.3m) · 3 예상 경로 교차(≤2.5m) · 4 스윙 교차 · 5 근접(≤1.3m) · 6 먼 장애물. 같은 등급은 간격 → 경로 거리.
시점(`viewPolicy.wantTop`): 5·6등급은 이전 그룹 규칙(`wantGroups` — 측면 위협이면 측면뷰, 아니면 기본 카메라), 진행 방향 정면은 1·2등급이면 집중 탑뷰·3등급이면 그룹 규칙(`risk.ts` 매우 근접 0.75m 이하면 집중 탑뷰, 아니면 기본 카메라), 측면/모서리는 그 쪽 측면뷰(가려지면 모서리가 보이는 집중 탑뷰), 진행 반대쪽 모서리 스윙은 그 방향 집중 탑뷰. 1·2등급은 확인 지연·쿨다운 없이 즉시. 수동 선택 우선, 기어 변경 시 기본 카메라(집중 탑뷰는 기준 카메라가 바뀔 때만 해제).
정지 중: 기어 변경 때보다 핸들을 3° 이상 돌리거나 1·2등급이면 자동 시점 허용(이전: 시속 1km 이상 이동 필요).
단위 시나리오: 좌 0.2/전 1.5 → 좌측, 우 0.3/후 1.2 → 우측, 전 0.4/좌 0.8 → 전방, 좁은 통로, 후진 앞 스윙, 정차 중 조향, 볼라드+벽, P/N. 숫자는 디버그 로그(`Game.rankOut`)에만.

## 4륜 예상 이동선 (`guidelines.buildWheelPaths`)

앞바퀴 2(실선) · 뒷바퀴 2(점선, 따라가는 궤적) · 조향 반대쪽 앞 모서리 스윙(주황 점선) · 장애물과 처음 닿는 지점(빨강). 강체 기구학(물리와 같은 식) — 후진은 실제 후진 경로(좌우 반전 아님). 입력은 **실제 전륜 조향각**(핸들 ±540° 와 다름). 설정 "서라운드뷰 예상 이동선: 상세(4륜)/기본". 카메라 영상 가이드라인과 같은 `pathOfPoint` 를 쓴다.
※ 이전 규칙 "서라운드에는 흰 예측선 2개 외 금지" 는 이번 지시로 바뀌었다(기본 모드에 그대로 남김).

## 기계식 비상 수동복구 (`src/mech/recovery.ts`)

모드: 자동 → 비상정지(X) → **제어반(Z) "비상 수동복구 진입"** → 개별 조작 → **"복구 완료"**(검사 통과 시) → 정상 대기 또는 출차 대기.
- 셔터: 열기 · 닫기(문 구역 비어 있을 때만) · 정지 · 긴급 개방(2배) · 개방률 표시
- 캐리지: 층 상승/하강 · 정지 · 1층 복귀 · A/B 이송 · 중앙 (승강=중앙+셔터 닫힘, 이송=보관층 정위치)
- 팔레트: 슬롯 인출 · 슬롯 안치 · 승강장 공급 · 빈 팔레트 회수 · 승강장 수동 안착 (안치/인출은 정상 입출고와 같은 stored/picked 이벤트 → 차량 모델 소유권 그대로)
- 턴테이블: 좌/우 회전 · 정지 · 초기 방향 (1층 중앙·셔터 닫힘)
- 전체 정지
- 제어반 표시: 시설 · 모드 · 오류 코드(E-10 1층 아님, E-11 중앙 아님, E-20/21 팔레트, E-30 턴테이블, E-40 셔터, E-50/51 차량 정보 불일치, E-60 동작 중) · 셔터% · 캐리지 층 · 이송 위치 · 팔레트 위치 · 탑재 차량 · 슬롯 점유 · 복구 가능 여부
- 불변식: 진입 시점 차량 ID 집합 유지(삭제·중복·새 생성 없음), 다른 시설 상태 불변, 복구 전 자동 입출고 불가
- 모든 시설(4/6/8/12층 및 부속 구역) 공통(같은 상태기계)

## 기타 결함 수정

- **전체 회귀에서 찾은 v0.6.1 회귀(수정 완료)**: 처음 구현은 1순위가 5등급(일반 근접)이면 시점을 유지해서, 이전부터 있던 "측면 벽 0.8~1.0m → 측면뷰"와 "전방 0.45m(매우 근접) → 전방 집중 탑뷰"가 막혔다(스모크 465/483). 원인: 등급 임계(매우 근접 0.3m)가 `risk.ts` 의 시점 임계(0.75m)보다 엄격한데 그룹 규칙을 완전히 대체함. 수정: 순위는 1~4등급처럼 더 급한 경우에만 우선하고, 나머지는 그룹 규칙으로 되돌림. 재발 방지: `tests/riskRank.test.ts` 회귀 2건. 같은 회귀에서 반지름 0.15m 기둥 판이 원호 길이 기준으로 3조각이 되던 것을 현 길이 기준으로 고침(`tests/surfaceWarn.test.ts`). 스모크의 후방 경고 판 테스트는 이름 규칙만 `surf-*` 로 바꾸고 "장애물 면 위·장애물 폭 이내" 조건을 추가(약화 아님). `e2e-v060` 의 카메라 전용 가림 물체 수 1→5 는 승강탑 기둥 윗부분 추가에 따른 의도된 변경.

- 승강탑 모서리 기둥 4개가 시각 모델에만 있고 충돌체가 아니었다 → `ms-col-0~3` 충돌체 + 위쪽은 카메라 전용 가림 물체. 측면/집중 탑뷰 구도 검사가 카메라 전용 물체(상인방·안내판·기둥 윗부분)까지 본다.

- 위험 순위: 매 프레임 장애물별 스윕(0.15m × 최대 2.5m, 히트점 수만큼) — 순수 JS, 단위 테스트 1회 ms 단위. 브라우저 FPS 측정은 회귀 실행에서 따로 하지 않았다(소프트웨어 WebGL 수치는 실기기와 무관).
- 서라운드 상세 이동선: 5개 경로 × 24점, 경로마다 주변 충돌체 교차 검사.
