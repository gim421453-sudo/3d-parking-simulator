v0.5.3 의 기계식 시설 모듈화(`src/mech/facility.ts`)와 통합 맵(`compose.ts`)이 이 방향의 첫 단계다. 아래는 이후 단계의 설계 메모이며
**지금 구현된 기능이 아니다**. 사용자 결정이 필요한 항목은 마지막 표에 모았다.

## 2. 필요한 확장 (순서 제안)
1. **큰 월드 좌표**: 현재 float32(three.js) 는 원점에서 ~수 km 이상 멀어지면 떨림이 생긴다. 해결: 월드를 **타일(예: 200 m)** 로 나누고 플로팅 오리진(카메라/차량 기준으로 장면 전체를 이동)을 쓴다. 물리/충돌은 float64(JS number) 라 문제 없음 — 렌더 전용 오프셋만 필요.
2. **구역 단위 렌더링**: `built.setViewCenter(x, z, radius)` 가 이미 통합 맵의 주차 차량 모델 거리 컬링을 한다. 도시에서는 구역(타일) 단위 로드/언로드 + LOD 로 확장한다.
3. **공간 분할 충돌**: 지금은 `colliders` 선형 검사(수백 개 규모). 도시 규모에서는 균일 격자(타일별 collider 목록)로 바꾼다. 인터페이스(`findVehicleCollision`, `raycast`)는 유지하고 입력 목록만 "차량 주변 타일의 collider"로 제한한다.
4. **도로 네트워크**: `nav/roadGraph.ts` 의 도로 그래프를 구역 간 연결(구역 입구 = 노드)로 확장. 도로별 제한 속도/차로 정보를 그래프 간선에 붙인다.
5. **동력계/성능 프로파일**: `ENGINE_PROFILES` + `VehicleSpec.maxSpeedFwd` 를 차종별 성능 데이터(토크 곡선, 변속비, 연비)로 확장. 전기차(소리/RPM 없음) 프로파일 추가 지점은 `engine.ts` 의 `profileOf`.
6. **주차 모듈 재사용**: 시설 키트(`facilityKit`) 를 일반 주차 구조(평면/다층/기계식) 전체로 일반화해 도시 블록에 배치. 시설 상태는 시설별 컨트롤러가 독립 보유(현재 구조 유지).
7. **미션/맵 데이터 분리**: 미션은 `MapMission` 으로 맵 데이터와 이미 분리. 도시에서는 "미션 팩"(스폰/목표/규칙)을 별도 파일로 두고 맵 ID 로 연결.
8. **제한 속도/단속**: 도로 간선 속성 `speedLimitKmh` + 위반 이벤트(미션 점수 연동). 지금은 없음.

## 3. 결정이 필요한 항목 (사용자)
| 항목 | 선택지 | 영향 |
| --- | --- | --- |
| 도시 규모 | (a) 동네 1 km² (b) 구 단위 10 km² | 타일 시스템/스트리밍 필요 여부 |
| 도로 데이터 | 직접 제작 / 실제 지도 데이터(OSM 등, 라이선스 확인 필요) | 에셋/라이선스 |
| 교통(NPC 차량/신호) | 없음 / 단순 NPC / 신호체계 | 물리·AI 범위 |
| 속도 규칙 | 제한 속도 위반 점수화 여부 | 도로 속성 데이터 |

> 이 문서의 어떤 항목도 아직 구현되지 않았다. 구현 시작 전에 위 표의 결정을 받는다.
