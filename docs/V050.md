## 2. P0-B 승강기식(팔레트형) 기계식 주차장 — `mechpark`
> 시뮬레이션용 **가상 장치**다. 법규 인증 사양이 아니다. V홈 정확한 깊이/피치는 확인하지 못해 시각 근사값을 썼다.

### 법규 기준(참고, **법정 최소**) 과 이 장치의 사양
| 항목 | 법정 최소(주차장법 시행규칙 제16조의2·제16조의5, 2026-07-27 기준으로 검토) | 이 장치 |
|---|---|---|
| 출입구 | 너비 2.4m × 높이 1.9m | 2.4 × 1.9 (모터 셔터, 안전센서) |
| 중형 주차구획 | 2.3 × 5.3 × 1.6 | 저장 베이 4칸(대형 팔레트) |
| 운반기 바닥 폭 | 중형 2.0m / 대형 2.15m | **2.15m**, 길이 5.6m |
| 사람 통로 | 0.5m × 1.8m | 표기만 (`limits.ts`) |
| **장치 허용 차량** | (제조사 사양) | 폭 ≤ 1.95m, 높이 ≤ 1.55m, 길이 ≤ 5.2m, 중량 ≤ 2300kg (`limits.ts`, 중량은 근사 제원) |

### 구성 (`src/maps/mapMechPark.ts`, `src/mech/*`)
- 대기 공간 → 출입문(개구부 2.4m) → 승강장(팔레트) → 저장 베이 4칸(높이 3m/6m, 좌우). 지상은 막힌 기계실.
- **팔레트**: 바퀴 홈 2개(중심 ±0.8m), 사이드 가이드(노랑/검정 줄무늬, 충돌체 `guide`), 진입 경고 띠, 앞바퀴 정지턱(홈 안).
- **V자(∧∧∧) 리브**: 홈 바닥에 `InstancedMesh` 로 실제 3D 지오메트리(홈당 약 33개 × 막대 2개, 꼭짓점이 앞). 텍스처가 아니며 홈 바닥 위 3cm 라 정상 진입을 막지 않는다.
- **전방 확인 거울**: 뒷벽의 `Reflector`(실제 반사 렌더, 가짜 이미지 아님). 승강장 근처에서만 보이고 갱신 FPS 제한(중/고 ≤20, 저 ≤10), 해상도 384/192.
- **문 안전센서**: 문 구역에 차체가 걸치면 닫히던 문이 다시 열림. 문이 완전히 닫히기 전에는 승강하지 않음(인터록).
- **입고 조건**(`machine.ts: checklist`): 치수/중량 허용, 팔레트 중앙 ±12cm, 방향 ±3°, 4바퀴가 홈 안, 가이드 침범 없음, 앞바퀴 정지턱 ±0.2m, 정차, P + 주차 브레이크, **운전자 하차 상태**(게임 상태이며 사람 감지가 아님), 문 센서 정상. 하나라도 어긋나면 거부하고 이유를 표시.
- **정지턱/가이드**: 앞바퀴가 정지턱을 넘으면 뒤로 밀어내고 속도 0. 가이드는 낮은 충돌체(h 0.3, 두께 0.3)라 차체가 침범하면 일반 충돌 처리(센서 높이 0.55m 아래라 PDC 에는 미감지 — 의도).
- **입고 순서**: 문 닫힘(2.5s) → 승강(1.6s/m) → 옆 이송(3s) → 저장. 차량은 팔레트 기준 상대 위치로 고정(운전 입력 차단). 비상정지(X) 시 정지, 해제 시 재개.
- **출고**: K → 옆 이송 복귀 → 하강 → 문 열림 → 탑승(G) 후 후진 출차. 출구 구역 정차 시 미션 성공(`mech-out` 은 양방향 헤딩 허용).
- **미션**: `mech-in-1`(정면 진입), `mech-in-2`(옆에서 접근), `mech-out-1`(출고). `MechInRunner` = 저장 완료 시 성공.
- **조작**: G 하차/탑승, J 입고, K 출고, X 비상정지 (+ 좌측 패널 버튼, 같은 `Action` 경로).
- 내비게이션은 이 맵에서 미지원(`noRoute`).
- **미구현**: 다중 차량 큐/동시 저장, 저장 중인 차량 모델의 상시 렌더 최적화(스테이션 근처 외에는 숨기지 않음), 감전/압착 등 사람 감지 시뮬레이션, V홈 실제 깊이 규격.

### 검증
- 단위: `tests/mech.test.ts` 22개(치수 거부, 정렬, 가이드/정지턱, 문 인터록, 상대 위치 불변, 비상정지, 5회 반복, 출고 미션 시작 상태 회귀).
- 브라우저(소프트웨어 WebGL): `scripts/e2e-mech.cjs`(진입→정지턱→하차→입고→승강→저장→미션 성공), `scripts/e2e-mech2.cjs`(출고→후진 출차→성공, 세단/폭 초과/SUV 높이 초과 거부), E2E v0.5.0 블록.
- 스크린샷: `docs/screenshots/v050/mech-*.png` (V홈 리브 위/후방, 접근/정지턱, 승강, 저장, 출고, 거부).

## 3. P1-C 전/후방 카메라 세로 경고 패널
- 이전: 차체 폭 ±0.35m 를 6칸으로 → 좌우 가장자리/모서리 밖 장애물이 패널에 안 잡힘.
- 이후(`overlay.ts: buildCameraTiles`, `tileLayout`): 차체 폭 밖 ±1.6m 까지 **0.3m 폭 타일(약 17칸)**, 범퍼 끝 옆 0.15m 의 모서리 히트도 포함. 타일은 여전히 실제 센서 히트가 있는 칸만, 표면 거리·충돌체 윗면 높이에 맞춘 반투명 세로 패널. 외곽선은 얇고 옅게 해 띠로 보이게 함.
- 테스트(`tests/overlay.test.ts`): 좌/우 가장자리 기둥, 중앙 차량 폭, 비스듬한 벽(칸별 표면 깊이 상이), 모서리 걸침, 히트 없으면 패널 없음.
- **미구현/한계**: 앞을 가리는 다른 물체에 의한 패널 가림(occlusion) 처리, 센서 히트점-투영 패널 위치를 픽셀 단위로 비교하는 별도 비교 도구, 좁은 기계식 입구/팔레트 가이드/정지턱 전용 시나리오 스크린샷.

## 4. P1-D 서라운드 거리색 경고선
- `drawWarnLines` 가 흰 예측선 2개 외에 `buildWarnLines`(실제 히트 구간, 0.4m 구간) 의 **얇은(2.4px) 단계색선**을 그린다. 색/단계는 PDC 설정(`sensorRange/Critical`)과 팔레트를 그대로 쓴다. 전체 링/큰 사각형/화살표/눈금 없음. 센서 전용 화면의 다색 PDC 는 그대로.
- 검증: E2E(감지 없음 → 색선 0 + 흰선 2, 후방 벽 → 색선 > 0 + 흰선 2), 스크린샷 `surround-warn-lines.png`.

## 5. P1-E 타이어 조향/회전
- 모든 카메라(서라운드 렌더 패스, 좌/우/전·후방 집중 탑뷰, 추적, 1인칭)는 **같은 차량 모델 객체**를 렌더하므로 바퀴 상태가 동일하게 반영된다.
- E2E 로 확인한 것: GLB 앞바퀴 조향 각(좌우 동일 부호), 주행 중 4바퀴 회전, 정차 시 회전 정지 + 조향 유지.
- **미확인(부분)**: 카메라별 화면 픽셀에서 바퀴 회전이 눈에 보이는지, 후진 시 역회전 시각 검증, 경사로/팔레트 위 바퀴 표현. 바퀴가 보이지 않는 시점에 가짜 바퀴 이미지는 만들지 않았다.

## 6. P2-F 3인칭 미러
- 상단 버튼(`mirrorToggle`, 키 U)으로 토글, 기본 OFF, `settings.thirdMirror` 로 저장/복원.
- ON: `MirrorSystem`(기존 1인칭 미러 렌더러)이 좌/룸/우를 실제 3D 장면으로 렌더하고 `MirrorOverlay` 가 화면 하단 중앙(계기판 바로 위)에 그린다. 15fps 이하(저사양 10fps), 소해상도. OFF 이면 렌더 호출 자체가 없다. 1인칭에서는 오버레이를 그리지 않아 실내 미러와 충돌하지 않는다. 기어 변경과 무관하게 유지.
- 테스트: `tests/mirrorOverlay.test.ts`(5개 화면 크기 레이아웃), E2E(기본 OFF/렌더 없음, ON 렌더, 기어 변경 후 유지, 1인칭 비충돌, OFF 렌더 중단).
- **미검증**: 기계식 입구/좁은 주차장에서의 시각 확인, 실기기 FPS.

## 7. 알려진 문제 / 다음 단계
1. BMW M4/X6 실모델: 사용자가 Sketchfab 로그인 후 GLB 를 받아 `public/models/` 에 넣고 라이선스(CC-BY 표기/상표) 확인 후 `spec.ts` 에 연결.
2. 컨셉 쿠페: 앞 방향지시등·DRL 지오메트리 없음, 실내 없음, 모바일 성능 미측정.
3. 기계식: 저장 중 차량 모델 가시성 최적화, V홈 실제 규격 확인, 사람 감지(안전 매트/광전) 시뮬레이션.
4. 패널 가림(occlusion), 카메라별 타이어 시각 E2E.
5. APK/ADB 작업은 보류(지시).
