# 향후 맵 개발 원칙과 엔진 한계

## 원칙: 맵은 "고정 제작"
- 주차장 종류, 주차칸 폭, 통로 폭, 차량 배치, 난이도는 **게임 안에서 사용자가 바꾸는 기능이 아닙니다.**
- 맵을 만들 때 사용자가 원하는 배치와 치수를 먼저 **확정**하고, 그대로 고정해서 제작합니다. (확정 전에는 임의로 대규모 배치를 만들지 않음)
- 맵마다 별도의 고정 데이터(`src/maps/mapXxx.ts`)와 모델 파일(`public/models/maps/xxx.glb`)을 두고, **소스 데이터와 모델 파일을 분리**해 새 맵을 쉽게 추가합니다. 충돌체/센서/미니맵/미션은 맵 데이터(Collider)를 읽고, 보이는 모델은 GLB 가 담당합니다.
- 추가 예정 맵(각각 별도 고정 맵): 주차타워, 나선형(골뱅이) 경사로, 좁은 골목길, 직각·평행·사선 주차장, 정비소.

## 맵 제작 절차 (사용자 확정 → 제작)
1. 사용자가 치수 확정: 구획 폭/길이, 통로 폭, 기둥 간격, 차량 배치, 출발 위치, 미션 종류
2. `MapData` 작성 (`docs/MAP_GUIDE.md`) + `tests/maps.test.ts` 가 자동 검증(시작 위치 충돌 없음, 목표 구획 진입 가능 등)
3. (선택) Blender 로 시각 모델 제작 → GLB (`docs/BLENDER_PIPELINE.md`) → 충돌체는 데이터에서 별도 정의
4. 실제 렌더링 스크린샷 + E2E 로 검증

## ⚠️ 현재 엔진으로 가능한 것과 불가능한 것

현재 엔진은 **2D 저속 평면 물리 + 단일 높이(0.55m) 수평 센서**입니다.

| 기능 | 현재 가능? | 필요한 확장 |
|---|---|---|
| 평면 주차장(직각/평행/사선 구획), 기둥, 벽, 좁은 골목 | ✅ | 사선 구획은 `slot.dir` 로 표현 가능 (미션 판정 지원) |
| 다층 주차타워, 층 이동 | ❌ | 차량 상태에 **높이(y)·층** 추가, 층별 충돌체 필터, 층 전환 판정 |
| 나선형(골뱅이) 경사로 | ❌ | 지면 높이 함수(`groundY(x,z)`), 경사에 따른 차량 피치/속도, 경사 위 충돌/센서 처리(센서 높이를 지면 기준으로 보정) |
| 천장/상부 구조물과의 높이 충돌 | ⚠️ 부분 | 충돌체의 `y0/h` 필드는 있음. 차량 높이 대비 천장 충돌 판정은 아직 없음 |
| 2주식 리프트(차량이 올라감) | ❌ | 차량이 지면 위로 올라가는 상태(수직 이동), 리프트 위 충돌/센서/카메라 규칙, 정비소 전용 상호작용 |
| 센서의 경사/다층 대응 | ❌ | 다중 높이 레이 또는 3D 레이캐스트(경사면 포함) |
| 카메라(경사/다층) | ⚠️ | 지면 높이를 따라가는 카메라 보정 필요 |

→ 주차타워/나선 경사로/리프트 맵은 **엔진 확장(3D 높이·경사·충돌)을 먼저 개발**한 뒤에 맵을 제작해야 합니다. 이는 2D 물리를 Rapier 같은 3D 물리로 바꾸거나, 현재 자체 물리에 높이/경사 개념을 추가하는 두 가지 방향이 있으며(후자가 변경 범위가 작음), 센서 로직을 지면 높이 기준으로 재정의해야 합니다. 이번 업데이트에서는 구현하지 않았습니다.
