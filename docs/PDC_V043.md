# PDC 정밀 개선 (v0.4.3)

## 1. 위험 판단 — 경고 단계와 화면 전환 조건을 분리
| 항목 | 이전 | 이후 |
|---|---|---|
| 센서 최대 감지 거리(기본) | 2.5 m | **3.0 m** (`sensorRange`) |
| 연속 경고(critical) | 0.3 m | **0.5 m** (`sensorCritical`) — 3.7km/h 에서 반응 0.3s + 3m/s² 제동 정지 여유(0.5m)와 같은 규모(`tests/risk.test.ts`). 실차 공식 수치 아님 |
| 색/경고음 단계 | 4단계(far/mid/near/critical) | **유지** (거리 → 단계 계산식 동일, 경고음 주기와 동기화 유지) |
| 3D 시점 전환 기준 | 센서 거리가 `near`(≈1.0m) 이하 + 광선 3개 + 0.3초 | **차체 외곽~장애물 표면 간격**(히트점→OBB) 측면 ≤1.3m, 전/후 ≤1.6m **또는** 접근 시간(TTC) ≤2.5s(간격 ≤2.4m) + 광선 2개 + 0.2초 지속, 해제는 +0.4m 히스테리시스 |
| 방향 판단 | 센서 그룹 | **히트점의 차체 기준 위치**(전/후: 차체 폭+0.5m 통로, 좌/우: 차체 길이+0.5m). 옆 벽이 앞으로 이어져도 전방 위험으로 오인하지 않음 |
| 측정(5km/h 후방 접근) | near 진입 간격 1.00 m | 새 위험 진입 **1.92 m**, 경고 시작 2.48 m (`tests/risk.test.ts` 로그) |

`pdc/risk.ts` 의 `RiskConfig` 는 `sensorRange/sensorCritical` 과 독립이다. 간격 숫자는 내부 계산 전용이며 UI 에 표시하지 않는다.

## 2. 시점 정책 (`pdc/viewPolicy.ts`, X6 전용 — M4 는 후방카메라만)
| 상황 | 시점 |
|---|---|
| 왼쪽만 / 오른쪽만 위험 | 좌측 / 우측 3D 뷰 |
| 양쪽 동시, 좁은 공간(좌우 ≤1.6m), 측면 + 전/후방 동시 위험, 측면뷰가 가려짐 | **전체 탑뷰** |
| 측면 장애물 ≤0.5m(히스테리시스 0.8m), 기둥/콘/드럼/가로등/나무 옆 | **확대 탑뷰**(topZoom) — 최소 높이 5.2m 로 상대 위치 판단 가능 |
| 전/후방만 위험 | 기본 카메라 유지 |
| 해제 | 1.6초 유지 후 기본 시점 복귀, 최소 유지 1.4s, 쿨다운 0.9s |
| 수동 선택 | 항상 우선 (자동 전환 정지) |
수동 순환: 자동 → 후방 → 전방 → 좌 → 우 → 탑 → 확대 탑 → 사선.

## 3. 카메라 프레이밍 (`pdc/framing.ts`, `pdc/visibility.ts`)
- 측면: 차체 측면 · 틈 중앙 · 장애물 표면이 모두 화면에 들어오는 위치/높이/FOV(42~78°)를 탐색. 후보마다 시야 가림(차체 높이, 충돌체 높이)과 카메라가 고체 내부인지 검사. 모두 막히면 `visible=false` → 정책이 전체 탑뷰로 전환.
- 탑: 차량 4모서리 + 장애물 히트점의 경계 상자로 중심/높이 결정(8~22m, 고정 12.5m 아님). 확대 탑은 위험 방향 중심, 5.2~13m.
- 10Hz 재계산, 카메라는 매 프레임 지수 보간. 감지가 잠깐 끊겨도 1.5초간 마지막 히트점 유지.
- 비용: `frameView` 평균 1.4ms (충돌체 400개, 서버 CPU. 실기기 수치 아님).

## 4. 카메라 영상 위 장애물 구역 (`pdc/overlay.ts` + `AssistPanel.drawOverlay`)
- 전/후방뿐 아니라 **X6 3D 측면/탑/확대 탑/사선**에도 표시. 센서가 실제로 맞춘 히트점의 좌우 범위 + 여유(0.12m), 깊이 0.45m 사각형을 지면(y=0.03)에 투영 → 장애물 표면과 일치.
- 위치/크기/투명도 보간, 감지가 사라지면 서서히 소멸. 단계 색은 PDC 팔레트와 동일.
- 3D 시점에서는 카메라→구역 중심 선분이 다른 충돌체/자기 차체에 가려지면 그리지 않음(구역을 만든 충돌체 자신은 제외).
- 높이 정보: 2D 센서로는 장애물 높이를 모르므로 지면 사각형만 표시한다(허공에 세우지 않음).

## 5. 예측 조향선
- 경로 계산은 기존 자전거 모델(`guidelines.ts`) 그대로 — 물리와 동일, 투영 때문에 축소/변형하지 않는다.
- 투영(`pdc/clip.ts`): 동차좌표 **근평면 클리핑 → 화면 사각형 클리핑**. 이전에는 NDC z 로만 걸러 카메라 뒤 점이 좌우 반전되어 영상 밖으로 뻗었다.
- 후방 카메라 = 후진 경로, 전방 카메라 = 전진 경로, X6 탑/확대 탑/사선에서도 바닥 좌표에 표시. 좌/우 경로 사이 예상 이동 범위를 옅게 칠한다(네 모서리가 모두 카메라 앞일 때만).
- 전/후방 카메라 마운트를 차체 표면(±L/2∓0.02)으로, near 0.05 로 조정 — 번호판이 near 평면에 걸쳐 잘리던 현상 방지.

## 6. 방향별 경고음 (`sensors/beepPlan.ts`, `beeper.ts`)
전 1250Hz/65ms, 후 920Hz/85ms, 좌·우 1080Hz + 스테레오 패닝 ∓0.7. 여러 방향이면 가장 가까운 방향 1개(직전 방향과 0.15m 이내면 유지). 주기·연속음은 기존 거리 연동 유지, 경고음 OFF/볼륨 설정 존중. 한계: 모노 스피커/한쪽 이어폰에서는 좌우 분리감이 제한되고, 독자 음원이며 실제 BMW 음원이 아니다. 실제 청취는 이 환경에서 검증하지 못했다(방향 선택·주파수·패닝 값은 단위/E2E 로 검증).

## 7. 1080° 핸들 (`core/wheel.ts`, HUD `#t-wheel`)
좌우 540°(총 1080°), 각도 증분 누적으로 여러 바퀴 연속, 점프(>110°)·중심 근처 입력 무시, 첫 손가락만 포인터 캡처(다른 손가락 입력 가로채지 않음), 앱 전환/일시정지/결과 시 해제. 핸들 540° = 바퀴 최대 조향각(`spec.maxSteer`). 설정: 조향 방식(회전 핸들/버튼), 감도, 복귀 속도. 실내 핸들 모델도 같은 매핑으로 회전. 미구현: PDC 탑뷰 핀치 확대.

## 8. 번호판 고정 오류
- 재현/측정: 번호판은 `bodyGroup` 의 자식으로 위치가 고정(주행/조향/회전/후진 중 차체 기준 좌표 불변 — E2E 검증). 그러나 번호판은 차종과 무관하게 `±(L/2+0.04)` 에 놓였고, 차체(lowerMesh)는 베벨 때문에 `L/2+0.035` 까지 나와 SUV 에서 번호판 겉면이 차체 면과 12mm 차이로 거의 같은 평면(안쪽 면은 차체 안)이었다. 또 후방/전방 카메라가 차체 안쪽 9cm 에 있고 near=0.1 이라 번호판이 near 평면에 걸려 영상 아래에서 잘려 보였다.
- 한 줄 원인(추정 포함): 고정 좌표 + 얇은 간격 → 깊이 정밀도가 낮은 환경(모바일 16bit 깊이 등)에서 Z-fighting/깜빡임, 카메라 near 걸침으로 앞뒤로 움직이는 듯한 시각 효과. 사용자 기기에서 직접 재현하지는 못했다.
- 수정: 차체 실제 외곽(경계 상자)에서 12mm 띄워 부착(`PLATE_STANDOFF`), `polygonOffset`, 카메라 near 0.05/마운트 표면, GLB 로 교체될 때 GLB 외곽에 번호판 재부착.
